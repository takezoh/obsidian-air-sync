## Implementation progress (2026-09-05)

Implemented supporting boundaries, with discriminating RED→GREEN tests:

- Store exact source/destination CAS, same-key and overlapping bulk relocation, atomic incompatible merge-base invalidation, and terminal-record-bound content refresh. Ordinary content commits now require exact CAS, including the absent-record expectation. Best-effort merge-base reads must also match the committed size/hash.
- Captured pure scope compatibility query, privately freezing pre-projection path surface and settings. Planning no longer supplies a live exclusion callback. Public fact binding consumes this query.
- Executor preserves admitted component order through publication, blocks suffix actions after prefix failure, pools only independent singleton transfers/matches, and holds the existing normal permit across the serial interval. Prior priority work drains before entry and newly queued priority work waits until exit. Public Admission supplies fact-bound components; exhaustive footprint/performance verification remains unfinished.
- Existing tracker generations now distinguish same-value file/folder rename reports recreated during a cycle, including return-to-origin mutations. No new retained state was introduced.
- The content comparer recognizes proven current equality against a stale baseline, while unproven equality remains a conflict.

Continuation progress: production `admitBatchObservation` now groups and binds current facts before content comparison; no leading `planSync` or action-derived coverage repair runs on this entry. The two original no-action alias witnesses were strengthened into public observation tests and pass. Rename actions carry a fixed equal/copy protocol, with capture before mutation, exact endpoint checks, terminal proof and source/destination publication expectations. Folder content actions feed their exact successful record receipts to parent bulk publication. The executor no longer runs the old fresh-state or case-alias-specific protocols, and the committer's unconditional delete/put/rewriting fallback and fresh-only publication API have been removed. `TerminalActionProof` is cycle-local execution output, not stored state.

The finalization module now owns the observation-to-checkpoint attempt wrapper, sibling settlement and single commit/abort closeout. Orchestrator consumes its clean/incomplete result for status and tracker acknowledgment; independent rename/folder completion predicates are removed. Positive integration fixtures explicitly model provider-confirmed post-write metadata. Separate public pipeline tests require request echoes to withhold publication and prove subsequent provider confirmation converges without another rename/write or recovery marker.

Further implemented: priority replacement now carries the exact successful terminal record rather than Set membership. All six recreated-source B pull/match/conflict → A match/conflict orderings are covered; prefix CAS failures block A and a subsequent ordinary observation converges. A foreign local destination version is captured and preserved even when auto-merge selects remote bytes. Stable metadata cannot disguise a mismatching read buffer in conflict preparation.

Parent terminal proof now checks each admitted retained descendant against its successful child record or unchanged baseline, plus final absence of deleted descendants and content of required preservation outputs. Content/identity substitution during native rename, deleted-child recreation, and preservation-copy tampering withhold the parent's atomic record rewrite. Successful child publications remain successful; no failure marker is written. A parent rename followed by a concurrent child edit converges through ordinary re-observation and pull. Unchanged child relocation is published only by the parent, without redundant child matches.

Acquisition obtains missing content facts at both reported endpoints (and already observed descendant entries), not just local rename destinations. It does not scan additional physical subtrees; the existing scope projection still controls which facts enter Admission. Hash and metadata from a resolved stat remain one version; cross-algorithm enrichment verifies the read buffer against the captured local hash before attaching a comparable remote hash. Pure rename uses committed local SHA/provider checksum fingerprints without a download when valid. Copy reuses the existing captured buffer for terminal verification. Parent proof adds one final stat per side per retained child; fallback reads concern only an affected endpoint whose metadata cannot prove its bytes. Call-count tests pin zero explicit content reads for proven pure rename/unchanged parent and one transfer read with no redundant destination read for the cross-algorithm copy case. `LocalFs.stat` itself may compute a hash by reading the affected file.

The existing writer/constructor/retained-field inventory is unchanged. Its scanner now recognizes destructured Store references and all exact CAS mutations; ten negative fixtures prevent these forms from evading detection. Removing the legacy conflict executor also removes `conflict.ts` from the Store reader/import inventory; it adds no reader or writer.

Latest continuation removed the action-input Admission API, `planSync`, the optimizer compatibility view, and dormant local/remote optimizer, local-normalizer and topology modules. Content-comparison tests now call the pure comparer directly; action construction and ordering belong to public Admission tests. The two retired optimizer suites (34 tests) asserted obsolete proposal-array rewrites, fallbacks and applied/skipped bookkeeping. Their safety scenarios now live at the current contract: native/case-alias file matrices; complete/nested/shallowest folder mappings; unknown scope/vacancy and contradictory identities; child deletion before parent with old/new baseline keys in both directions; and hidden-path adapter-boundary file moves with move/CAS interruption followed by ordinary convergence. Empty proposal-array identity and unsafe hash-difference fallback assertions were intentionally retired, not relaxed into a new authorization rule.

Ordinary push/pull and same-path conflict publication now require actual terminal endpoints, not fallback to pre-I/O metadata. Transfers bind their read bytes to current source facts and revalidate before the write. Additional checks are affected-endpoint stats, not a whole-vault scan. Parent receipt lookup walks the existing ordered success collection once per consumer; a 512-child test pins linear access without a receipt registry. Observation evidence uses the committed record key rather than the listing address for historical identity occurrences.

The AST guard now closes the content-comparer, fact-graph and identity-decision import ownership, bans retired action-first names, and pins fact-only observation/component fields. Existing durable owner and orchestrator-field inventories are unchanged. Positive Executor fixtures now require successful effects/publication as well as ordering/progress. Remote request-echo negative fixtures remain conservative.

Review repairs unify ordinary and renamed conflicts through one resolver: stable input capture, existing strategy selection, verification of policy-required preservation copies, then executor-owned original-path effects, terminal proof and exact publication. The former `prepareOnly`/`requiresPreparation` split, low-level `resolveWithStrategy`, legacy original-path writes and compensating merge rollback are removed. Resolver tests now assert selected bytes and unchanged originals; public executor tests prove actual writes and ordinary interrupted duplicate/merge convergence. Invalid JSON/Canvas merges retain duplicate fallback. Ordinary successful merge/newer-wins creates no unnecessary copies.

The shared `content-snapshot.ts` reuses the previous stable-capture mechanism for transfer and conflict. Hash-empty or opaque-checksum remote endpoints are valid transfer sources when stable current metadata or bounded exact-byte capture proves the input. Result-local `capturedInputs` contains only the two read witnesses required to revalidate sources before overwrite; it is discarded with execution, not a retained owner or operation ledger. Preservation and terminal checks reuse authoritative computable checksums, falling back to reads only for affected endpoints without that proof. A newly arriving rotation target is rejected, never promoted into permission to delete; deletion is fixed to the admitted, preserved additional remote version.

Local old-name recreation now binds and publishes the moved identity before the ordinary source-address push, with exact absent publication expectations. A destination's unrelated SyncRecord cannot settle a report whose source still exists: current source facts must account for the report, and unbaselined local reports bind before destination history. Public tests cover the unrelated-destination counterexample, both baseline modes, conflicts, prefix/suffix interruptions, and re-observation to a fixed point.

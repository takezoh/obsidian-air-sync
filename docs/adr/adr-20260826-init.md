# Adopt structured development documents

## Context

The repository already contains a structured change package and ADR alongside legacy
numbered ADRs without dev-docs frontmatter. New artifacts need a schema-validated,
relation-aware lifecycle, but initialization must not silently turn into a legacy
document migration.

## Decision

Adopt dev-docs format version 2 for structured artifacts. Commit the generated schemas,
lifecycle transition table, alias registry, and repository-local configuration. Lint
structured ADRs named `adr-*.md`; retain the legacy numbered ADRs unchanged until an
explicit migration is requested.

## Alternatives considered

- Migrate every existing ADR during initialization. Rejected because migration is a
  separate, broader change and was not requested.
- Exclude all ADRs from lint. Rejected because new structured ADRs must be validated.

## Consequences

New structured artifacts receive mechanical validation and lifecycle support. Legacy
numbered ADRs remain outside that lint target temporarily, and existing Markdown content
is otherwise unchanged.

The alias registry now also resolves the canonicalized ADR 0001 identifier and the
late-bound execution decision. This extends the initialized relation mechanism without
migrating or rewriting the remaining legacy numbered ADRs.
